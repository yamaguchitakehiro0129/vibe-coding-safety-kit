# Vibe Coding Safety Kit

AIに書かせたコードを、安全に世に出すための索引。

---

## はじめに

AIがコードを書く時代になった。

非エンジニアが、1週間でアプリを作る。
週末の思いつきが、月曜には動いている。

それは、悪くない。
むしろ、素晴らしい。

ただ、そのレベルのものを、そのまま世に出すのは別の話だ。

「動いた」と「届けていい」は、違う。
「便利」と「安全」も、違う。

このリポジトリは、その違いを埋めるための索引である。

---

## このキットが扱うこと

ソフトウェアエンジニアリングは、半世紀かけて失敗を蓄積してきた領域だ。
セキュリティ、コスト、法規制、データ設計、性能、運用。

どれも、誰かが痛い目を見た跡から生まれた知恵である。

AIがコードを書けるようになった今、
その知恵に触れずに本番リリースする人が増えている。

このキットは、その人たちのために用意された。

* 何を確認すれば、最低限の事故を防げるか
* AIに何を聞けば、欠けている観点を補えるか
* どこまでが「個人で出していい範囲」で、どこからが「プロに頼むべき範囲」か

これらを、6つの観点で整理している。

---

## 6つの関所

リリース前に、必ずこの6つを通る。

1. [**セキュリティ**](checklists/01-security.md) — 譲ってはいけない最低線
2. [**コスト**](checklists/02-cost.md) — 寝ている間に請求は跳ねる
3. [**法規制**](checklists/03-legal.md) — 知らなかったは通用しない
4. [**データ設計**](checklists/04-data-design.md) — コードは直せても、データ構造は直せない
5. [**性能**](checklists/05-performance.md) — 何人まで耐えるかを知る
6. [**運用と障害対応**](checklists/06-operations.md) — 起きてからでは遅い

このキットの背景にある、IPA・OWASP・経済産業省・総務省などの公式資料は、
[References](references.md) にまとめてある。

## 2つの入口

このキットには、想定する読み手が2種類いる。

### 完全初心者ルート

Lovable、Bolt、Cursor、Claude Code を使い始めたばかりの人へ。

技術用語を最小化した、最初の通り道がある。
「まず、これだけは確認する」というレベルの索引である。

→ [はじめての人へ](docs/getting-started.md)

### 中級者ルート

個人開発でリリース経験がある人、スタートアップの初期メンバーへ。

各観点をより深く扱い、プロダクション運用までを射程に入れている。
「動かし続けるために何を整えるか」という索引である。

→ [中級者向けの索引](docs/intermediate.md)

## このキットの使い方

このキットは、読み物ではない。
通読を目的とした文書ではなく、必要なときに開く索引である。

使い方は3つ。

**ひとつ。** 作っているものに関係しそうな章を眺める。
知らない用語を見つけたら、AIに「これを初心者にもわかるように教えて」と聞く。

**ふたつ。** リリース前のチェックリストとして使う。
6つの関所を、自分のプロジェクトに当てはめながら通過する。

**みっつ。** AIにレビューを依頼するときの観点として使う。
[ai-prompts/](ai-prompts/) に、用途別のプロンプトが置いてある。

全部を理解する必要はない。
今日のあなたに必要な、2つか3つを拾えばいい。

---

## このキットが扱わないこと

このキットは、コードの書き方を教えるものではない。
プログラミング言語の文法、フレームワークの使い方、AIへの指示の出し方は、別の場所で学んでほしい。

このキットが扱うのは、「書けたあと」の話である。

書けたものを、誰かに使ってもらう前に。
動いたものを、明日も動かし続けるために。

そのために必要な観点だけを、ここに置いている。
