# AIにセキュリティレビューを頼むためのプロンプト

AIに「このコードをセキュリティレビューして」と漠然と頼んでも、
表面的な指摘しか返ってこない。

観点を指定すると、レビューの質が上がる。
このページは、その観点を渡すためのプロンプト集である。

---

## 全体レビュー（最初に使う）

```
以下のコードを、セキュリティ観点でレビューしてください。
特に以下の観点を網羅的にチェックしてください：

1. シークレット管理（APIキー・パスワード・秘密鍵がコードに直書きされていないか）
2. 認可（IDORなど、ログイン後の権限チェックが抜けていないか）
3. 入力検証（サーバー側のバリデーションが入っているか）
4. SQLインジェクション・XSS・コマンドインジェクションのリスク
5. ファイルアップロードの扱い（拡張子・サイズ・パストラバーサル）
6. エラーメッセージで内部情報が漏れていないか
7. 依存ライブラリの怪しい挙動

各指摘について、以下の形式で出力してください：
- 該当箇所（ファイル名・行番号）
- リスクの説明
- 修正の方針
- 修正コードの例
```

## IDOR（不正なオブジェクト参照）の検査

```
以下のAPIエンドポイントを見て、IDORの脆弱性がないか確認してください。

確認の観点：
1. リクエストパラメータでIDを受け取っているか
2. そのIDで取得するデータが、ログイン中のユーザーのものか確認しているか
3. 「URLのIDを書き換えただけで他人のデータが取れる」状態になっていないか

該当するコードの抜粋とともに、問題があれば指摘してください。
```

---

## 入力検証の検査

```
以下のコードで、ユーザー入力の扱いをチェックしてください。

確認の観点：
1. クライアント側だけでバリデーションしていないか（サーバー側でも同じチェックが入っているか）
2. 数値・日付・文字列長などの境界値チェックは十分か
3. 特殊文字のサニタイズは適切か
4. ファイルアップロードがある場合、拡張子・サイズ・MIMEタイプの三点を見ているか
5. パストラバーサル（../など）の対策があるか
```

---

## 依存ライブラリの検査

```
以下のライブラリを使う前に、安全性を確認してください。

ライブラリ名: [ここに名前]

確認の観点：
1. 公式リポジトリ（npm / PyPI など）に存在するか
2. 最終更新が直近1年以内か
3. メンテナの活動状況
4. 既知の脆弱性（CVE）がないか
5. ライセンス（GPL系を商用クローズドで使うとリスク）
6. 似た名前のライブラリと混同しやすくないか（タイポスクワッティング）
```

---

## 認可ロジックの検査

```
以下のコードに対して、認可（権限チェック）の観点でレビューしてください。

確認の観点：
1. APIのすべてのエンドポイントで、認証が必須になっているか
2. データを返す前に、リクエスト元ユーザーの権限を確認しているか
3. 管理者権限とユーザー権限が、適切に分離されているか
4. 権限のないリソースにアクセスしたとき、適切なエラー（403 / 404）を返すか
5. テナント境界（マルチテナントの場合）が、サーバー側で強制されているか
```

---

## エラー出力の検査

```
このアプリケーションのエラー処理を確認してください。

確認の観点：
1. 本番環境で、スタックトレースがユーザーに見える状態になっていないか
2. エラーメッセージにDBのテーブル名・カラム名が露出していないか
3. ファイルパスが、エラー出力に含まれていないか
4. SQL文そのものが、エラーに含まれていないか
5. 開発モードと本番モードの切り替え設定があるか
```

---

## ログの検査

```
このアプリケーションのログ出力を確認してください。

確認の観点：
1. パスワード・APIキー・秘密鍵がログに出ていないか
2. クレジットカード番号・個人情報（氏名・メール・住所）がログに出ていないか
3. ログレベル（INFO / WARN / ERROR）が、適切に使い分けられているか
4. ログから、後で問題を追跡できる十分な情報が記録されているか
5. ログの保存先が、複数箇所（外部SaaSなど）に分散されているか
```

---

## 使い方の指針

ひとつのコードに対して、上のプロンプトを順番に投げる。

最初は「全体レビュー」で、ざっくり問題を出してもらう。
そこで挙がった項目を、個別のプロンプトで深掘りする。

そしていちばん大事なこと。

AIの指摘を、鵜呑みにしない。
AIが「問題ない」と言ったコードに、本当に問題がないかは、人間が確かめる。

AIは、見落とすことがある。
それを前提に、レビューの一手段として使う。
