# AIに意味のあるテストを書かせるためのプロンプト

「テストを書いて」と頼むと、AIはハッピーパスだけを書く。
あるいは、モックだらけで何もテストしていないコードを返す。

意味のあるテストにするには、ステップを分けて指示する。
このページは、そのステップ集である。

---

## ステップ1：仕様書を作らせる

いきなりテストを書かせない。
まず、テスト対象の仕様を、AI自身に言語化させる。

```
今回実装した [機能名] について、仕様書を作成してください。

仕様書には以下を含めてください：
- 機能の目的
- 入力と出力
- 正常系の挙動
- 異常系の挙動（エラーケース、例外、境界値）
- 副作用（DB更新、外部API呼び出し、ファイル書き込みなど）
- 前提条件と事後条件
```

仕様書を読んで、抜けがないか確認する。
疑問があれば、ここで聞く。

---

## ステップ2：テストケースを洗い出させる

仕様書ができたら、そこからテストケースを抽出する。

```
先ほどの仕様書から、テストケースを網羅的に洗い出してください。

各テストケースについて、以下を明示してください：
- ケースの名称（仕様として読める形で）
- 検証する観点
- 自動テストでカバーすべきか、人的に確認すべきか
- 単体テスト・結合テスト・E2Eテストのうち、どのレベルが適切か

これをドキュメントとしてまとめてください。
```

ドキュメントを読んで、抜けがないか確認する。
重要なケースが含まれていなければ、追加を指示する。

---

## ステップ3：単体テストを実装させる

テストケースが固まってから、初めて実装に入る。

```
先ほどのドキュメントの「単体テストでカバーすべき範囲」を、実装してください。

実装の方針：
- テスト名は、仕様として読める形にする（例：「注文金額が0円のときは注文を拒否する」）
- Arrange / Act / Assert の構造を明確に分ける
- モックは最小限にする
- テストが、実装の詳細ではなく振る舞いを検証している状態にする

実装後、ドキュメントに「実装済み」のステータスを記載してください。
```

---

## ステップ4：結合テストを実装させる

単体テストだけでは、機能間の連携が確認できない。

```
先ほどの仕様書を見直して、結合してテストすべきケースを洗い出してください。

例：
- DBへの書き込みと読み込みが、正しく連携しているか
- 外部APIを呼ぶ箇所が、想定通り動くか
- 認証から認可までの一連の流れ

ドキュメントに、結合テストのケースを追加してください。
そのうえで、実装を進めてください。
```

---

## ステップ5：意味的なつながりを補う

AIは「機能Aを使った後で機能Bを使う」のような、シナリオベースのテストを書かない。
ここは、人間が補う。

```
以下のシナリオを、テストとして実装してください。

シナリオ：
1. ユーザーが商品を注文する
2. 在庫が減ったことを確認する
3. 同じユーザーがキャンセルする
4. 在庫が元に戻ることを確認する
5. キャンセル後、再度同じ商品を注文できることを確認する

各ステップで、データの状態が想定通りかを検証してください。
```

---

## レビューの観点

AIが書いたテストを、必ず自分で読む。
読めないなら、AIに「このテストが何を検証しているか説明して」と聞く。

確認の観点：

* テスト名が、仕様として読めるか
* Arrange / Act / Assert が分離されているか
* モックが多すぎないか（モックだらけのテストは、コードがモックを呼んだかしか確認していない）
* 実装の詳細に依存していないか（内部変数名やプライベートメソッドをテストしていないか）

---

## やってはいけないこと

* 「テストを網羅的に書いて」と一発で頼む（モックだらけの無意味なテストになる）
* AIが書いたテストを読まずに、グリーンになったから合格とする
* カバレッジ100%を目標にする（カバレッジ100%でもバグはある）
* テストの中で、テスト対象を直接呼び出さずモックだけで済ませる

---

## 補足：テストが落ちたときの対応

AIにテストを修正させるとき、こう聞く。

```
このテストが落ちています。

落ちた理由を、以下の観点で分析してください：
1. 実装にバグがある
2. テストの期待値が間違っている
3. 仕様の解釈が、実装とテストで異なっている

それぞれの可能性について、根拠とともに説明してください。
そのうえで、どちらを直すべきかを提案してください。
```

「テストが通るように修正して」と頼むと、AIは仕様を捻じ曲げてでもテストを通そうとする。
それでは、テストの意味がない。
